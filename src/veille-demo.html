Veille — l'invité QNX 8.0, en direct

Veille est un moniteur patient dont la latence capteur→alarme est bornée et prouvée par exploration exhaustive des états de défaillance (IEC 62304, IEC 60601-1-8). Pour montrer que la chaîne tourne vraiment sur la cible, le cœur C de Veille est compilé par qcc pour QNX 8.0 et embarqué dans une image invitée : ci-dessous, il s'exécute dans QNX, pas dans une simulation sur l'hôte.

L'invité, en direct

Voici un invité QNX 8.0 (QNX qnxqemu 8.0.0) qui tourne réellement sous QEMU : au démarrage il explore les 4 800 états de la chaîne, rejoue 600 échantillons avec pannes injectées, démarre le gestionnaire de ressources /dev/veille, puis un client mesure 200 allers-retours. L'écran de gauche est la console VGA de l'invité : elle affiche une phase complète à la fois (80×25, écran effacé entre les phases) ; les boutons injectent des touches dans la VM. La console de droite est le port série, qui déroule le même scénario en texte.

Ce qui s'exécute dans l'invité

L'écran VGA de l'invité fait 80×25 : une démo qui défile n'est pas une démo visible. Le scénario est donc joué en quatre phases, chacune tenant dans l'écran et effaçant la précédente — six secondes par phase, trois cycles, puis l'invite reste interactive (les boutons de la page injectent leurs touches dans l'invité QNX 8.0).

PhaseCe que l'écran affiche
1/4 — preuveexploration exhaustive : VEILLE_PROOF_COMPLETE bound=200 states=4800
2/4 — simulation600 échantillons, pannes injectées : 291 alarmes physiologiques, 8 techniques, marge 200 ms, L_measured <= B_proof
3/4 — signal brutles quatre états capteur : figé / tachycardie / mort / régulier, avec latence et borne
4/4 — ciblele gestionnaire de ressources /dev/veille (QNX, SCHED_FIFO 62), 200 allers-retours mesurés, verdict

Pièges QNX 8.0 réellement payés pour cette image : sans disque, le ksh de l'invité ne peut ni créer de tube ni faire de substitution de commande, et l'image n'embarque aucun printf — le scénario embarqué n'utilise donc que echo et des redirections par fichier. La console VGA est un terminal texte (l'image socle n'a pas de pilote d'affichage).

L'invite reste interactive après la démo

Quand le scénario a fini ses trois cycles, l'invité ne s'éteint pas : il rend la main sur un shell QNX 8.0. Les boutons de la page injectent leurs touches dans la VM — on peut donc interroger la cible depuis le navigateur. Tapé depuis la vitrine :

# uname -a
QNX localhost 8.0.0 2026/06/05-16:26:03EDT x86pc x86_64
# ls
bin  dev  proc  tmp  usr
#

C'est la même session que celle qui a joué le scénario : une invite qui répond, c'est une invite vivante, pas une capture d'écran.
