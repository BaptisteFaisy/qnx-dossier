Tamis — l'invité QNX 8.0, en direct

Tamis analyse statiquement une politique de sécurité QNX (secpol) et prouve l'accessibilité des privilèges avant le déploiement. Pour montrer que l'outil marche sur une vraie cible — et pas sur une simulation — le cœur C de Tamis est compilé pour QNX 8.0 par qcc et embarqué dans une image invitée : ci-dessous, il tourne réellement, dans QNX, sur une politique QNX 8.0 réelle.

L'invité, en direct

Voici un invité QNX 8.0 qui tourne réellement sur le serveur (r630, SDP 8.0 installé, QEMU) : il démarre, analyse la politique embarquée (politique.secpol) et affiche les verdicts. L'écran de gauche est la console VGA de l'invité (les boutons injectent des touches) ; la console de droite est le port série, où se déroule le même scénario.

Ce qui s'exécute dans l'invité

Le scénario joue cinq commandes de l'outil, dans la cible :

tamis reach   /proc/boot/politique.secpol --src app_tiers --dst pompe_critique
tamis lint    /proc/boot/politique.secpol
tamis explain /proc/boot/politique.secpol --src app_tiers --dst pompe_critique
tamis proof   /proc/boot/politique.secpol --src app_tiers --dst pompe_critique
tamis version

Sortie réelle relevée dans l'invité (console série) :

ERROR  TAMIS_PATH_FOUND  demo.secpol  app_tiers -> pompe_critique (3 sauts) : settypeid,settypeid,settypeid
INFO   TAMIS_OK  demo.secpol  Pourquoi ce refus : app_tiers atteint pompe_critique via la chaîne
      app_tiers →(settypeid) journal →(settypeid) diag →(settypeid) pompe_critique.
      Correctif minimal : retirer la règle settypeid (dernière arête avant pompe_critique) tue ce chemin.
WARN   TAMIS_MISSING_DEFAULT_SPAWN  demo.secpol  default_spawn_type absent (trou S7)
ERROR  TAMIS_INTERFERENCE_POSSIBLE  demo.secpol  app_tiers -> pompe_critique (3 sauts)

La politique analysée est le format QNX 8.0 réel : c'est le fichier que le compilateur officiel secpolcompile accepte (0 erreur), pas un format provisoire.
